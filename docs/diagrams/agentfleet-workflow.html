AgentFleet · System Walkthrough

How a task becomes a pull request

AgentFleet is a self-hosted agentic SDLC framework for a small team: a person opens a task in Zulip, a sandboxed dsh worker branches, implements, tests, and opens a PR, and a human merges it by hand. This walks the full loop — project setup, task assignment, agent execution, human touchpoints, and where each piece runs.

01

Setting up a project

A project is registered once, from a manifest the team edits by hand — not from a UI form.

02

Assigning work: feature → tasks

A feature opens a Zulip topic. Tasks arrive as a reviewed tasks.md from Spec Kit planning — not typed ad hoc into chat.

03

The execution loop

Once a task is QUEUED, the supervisor spawns a disposable container. The agent works inside a git worktree; anything that crosses a boundary — spawning, asking, opening a PR — is mediated by the control-plane API and logged as an event.

04

How the team talks to agents — and back

Two tools, never merged: an answer is data and can never itself grant permission.

05

Where it runs

One machine, one Podman Compose stack, four network zones. The runner never sees the internet or the container socket directly.

Compute

One VPS or bare-metal host. Rootless, daemonless Podman — no privileged host socket to guard.

State

Postgres on the same box; hourly dumps (7d) + daily (30d), shipped off-machine.

Human channel

Zulip Cloud, hosted, free tier — not self-installed.

Secrets

.env at mode 600, SOPS + age for anything committed. No Vault at this scale.
